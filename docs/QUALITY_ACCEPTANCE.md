# 总结质量固定集执行协议

质量验收不是让模型自由发挥后再凭感觉判断。每次付费调用前先冻结样本、期望和预算，调用后只按本文件核对。

## 最小固定集

| 样本 | 主要维度 | 通过条件 |
|---|---|---|
| 合成固定集 `quality-fixed-set-v1` | 多人观点、反讽、引用、音画冲突 | 分开归属陈岚与周凯；不把反讽当正面表态；区分老板引语与主持人立场；同时保留旁白 92% 和画面 29% 并指出冲突 |
| 公开多人视频 | 真实语速、剪辑、多人观点 | 至少抽查三名发言人，核心立场均正确归属，不把对手观点写给本人 |
| 偏好优先级 | 长期偏好与本次要求冲突 | 本次要求胜出；长期偏好只补充不冲突部分；既有正式笔记不被覆盖，新结果进入候选目录 |

合成固定集由 `scripts/build-quality-fixture.ps1` 在 Windows 本机离线生成，不下载素材、不包含真人数据、不调用模型。它故意构造可验证的多模态矛盾；不能替代公开真实视频，但能避免“看起来还行”式验收。

## 付费边界

1. 用户必须先明确批准本轮总预算和最大调用次数。
2. 每个样本最多一次 Kimi 调用；工具失败不自动付费重试。
3. 调用前记录该稳定身份的历史计数、正式笔记和 manifest 状态；已有同请求完成态时不得冒充新测试。
4. 调用后记录模型、usage、估算费用、输出路径、历史计数变化、清理状态和人工判定。
5. 报告只保存数值、稳定身份和判定，不保存 Cookie、签名媒体地址、提示词、reasoning 正文或逐字稿全文。

## 人工判定

每个维度使用 `通过 / 失败 / 无法判断`，并写出可定位的证据摘要：

- `通过`：输出明确覆盖预先冻结的事实或冲突，且没有归属反转；
- `失败`：遗漏关键维度、合并不同人物立场、把反讽写成字面事实、擅自消解模态冲突，或单次要求没有覆盖冲突的长期偏好；
- `无法判断`：源视频本身没有足够证据，不能按通过计数，也不能靠标题或网页简介补足。

只有合成固定集、公开多人视频和偏好优先级都完成，才能勾选相应质量项。逐字稿增强版仍需独立真实视频闭环，不能由本固定集替代。
