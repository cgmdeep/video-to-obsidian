# 视知库本地版阶段计划

更新时间：2026-09-30。本计划以公开 Alpha 的真实用户闭环为目标；比赛材料在产品闭环完成后制作，托管服务、支付和公共机器人不进入当前主线。

## 上线冲刺模式（2026-09-30）

当前不再扩展功能，先冻结一个可公开下载、可录制、可复现的 Windows Alpha。`v0.1.0-alpha.10` 已完成正式 Pre-release、主线 Windows 编译与测试，并补齐配置完成后自动打开 Obsidian 知识库和 ZCode 专用工作区；现在执行 COS/官网切换、xos 图形复验和最终闭环冻结。

上线/录制前只保留以下最小闸门：

- [x] 官网、COS 和 GitHub 使用同一 Windows 安装包、版本与 SHA-256；
- [x] ROG 专用普通账户 `VTOAcceptance` 已与主账户隔离并完成旧测试环境清理；
- [ ] 从生产官网完成浏览器下载和图形首装；
- [ ] 用户完成 Kimi Key、B站和 ZCode 官方微信 Bot Channel 的必要登录，并通过免费“检查系统”；
- [ ] 一条 15–30 分钟 B站视频从微信进入，在 Obsidian 生成正式笔记；
- [ ] 原样重发同一链接命中完成态缓存，不新增付费调用和重复笔记；
- [ ] 导出脱敏诊断并完成只读 Vault 审计，随后冻结 `alpha.10`，只修复 P0 阻塞问题。

以下工作不阻塞本次上线和录制：全新账户抖音复测、双平台完整陌生用户路径、20 人体验、真实上游故障演练、逐字稿增强版完整回归、Mac 公开发布与签名公证、ICP备案后的品牌下载域名、托管服务、支付和账号系统。此前已经通过的抖音真实闭环可作为平台技术证据，但不得冒充本轮陌生账户复测。

若免费闸门或 B站首条真实闭环失败，只修复该阻塞，不添加新功能；若最小闸门全部通过，即可把 `alpha.10` 用于公开 Alpha 和产品录制，宣传口径仍严格限制在实际通过的范围内。

## 产品边界

当前产品是用户自己电脑上的本地系统：微信负责提交，ZCode 官方 Bot Channel 负责连接用户自己的微信，本项目负责下载和分析，Obsidian Vault 负责保存结果。用户使用自己的平台账号和 Kimi Key。电脑与 ZCode 必须保持运行。

## P0：可下载、可安装、可验证

状态：进行中。`v0.1.0-alpha.10` 的 Release、CI 与 Security 已成功，同版三项发行资产已上传 COS；等待对象公有读与公共回读后切换 EdgeOne 生产官网。

- Windows 单文件安装器和版本化 GitHub Release；
- 国内下载镜像使用 COS 的版本化对象路径，官网展示准确体积和 SHA256；
- COS 存储桶保持私有；备案前仅对版本化发行对象单独开放公有读，官网使用 COS 官方 HTTPS 直链并配置流量告警；备案后再切换受控品牌下载域名；
- 官网不得把尚未验收的 Mac、云端账号或公共机器人写成已上线；
- Mac 版本在独立工作树完成，不阻塞 Windows 主线。

完成门槛：官网入口能下载与 Release 相同哈希的安装包，安装页明确 Alpha、文件体积、首次联网下载量和未签名风险。

## P1：普通用户首次使用闭环

状态：单文件图形安装、受管工作区路径复制与 ZCode 启动传参、脱敏诊断导出、双平台隔离 Firefox 启动以及 Obsidian Vault 登记/配置保护/唤起动作已在干净 Windows Runner 通过真实按钮验收；ROG 既有安装已从生产 COS 镜像安全修复到 alpha.8，交互会话免费体检 11 项全部通过，Vault 与工作区保持一致。上线冲刺先验收新用户亲自输入 Key、B站扫码、绑定 ZCode 微信、通过免费体检并完成首条 B站入库；双平台完整陌生用户路径在上线后补齐，执行口径见 [`FRESH_USER_ACCEPTANCE.md`](FRESH_USER_ACCEPTANCE.md)。

- 安装、修复、卸载、打开 Vault、打开平台登录、复制 ZCode 工作区路径；
- 无 Coding Plan 时可复用用户自己的 Kimi Key配置 ZCode 模型；
- 免费体检和脱敏诊断报告；
- 安装器中的下一步只描述用户动作，不暴露 Python、MCP、Cookie 文件等实现细节。

完成门槛：一台没有作者私人配置的 Windows 11 普通账户，仅依靠安装器界面完成到微信发送“检查系统”。

## P2：笔记一致性与本地知识库

状态：工程闭环已完成。主线测试覆盖旧版/新版身份识别、重复提交与 Vault 外运行数据；ROG 实库审计为 96 个 Markdown、5 个受管身份、0 个重复组、0 个不可读文件。跨设备同步仍按可选增强处理。

- 默认不生成逐字稿、不保留原视频；
- 新笔记按平台写入 Vault，运行状态、缓存、候选稿和视频归档保持在 Vault 外；
- 在整个 Vault 中按稳定身份识别旧版和新版笔记，禁止同一来源重复入库；
- 跨设备同步是可选增强，不作为基础依赖；产品只保证写入用户选择的本地 Vault。

完成门槛：旧版平铺笔记、新版平台目录和重复提交均不会产生第二份正式笔记；Obsidian 能立即看到写入结果。

## P3：双平台真实样本与质量固定集

状态：双平台典型样本、长视频与核心质量固定集已通过；戏仿/夸张/反问是后续扩展样本，不冒充已验收。

- 抖音短视频、B站典型视频（优先覆盖用户常见的 15–30 分钟内容）、B站长视频分别完成真实下载与 K2.7 入库；
- K3 只在用户明确说“使用K3深度分析”时启用，已有正式笔记时只写 Vault 外候选；
- 固定样本覆盖时间线、数字、多人观点、反讽/引用、音画冲突和偏好优先级；
- 每个付费用例必须先得到用户确认，并记录 usage、当日单价、输出路径和清理结果。

完成门槛：固定集人工核对完成，失败不能伪装成入库成功，缓存命中不会新增 Kimi 调用。

## P4：失败恢复与稳定性

状态：自动失败恢复、100 个无付费并发提交的单节点排队固定集、磁盘不足前置闸门、ROG 完成态缓存 30 轮/约 30 分钟巡检，以及 30 轮确定性 Kimi 503 故障恢复巡检已通过；真实平台登录失效、付费服务中断和 20 人体验仍待补充。

- 下载、代理、转写、Kimi、写入分别保留可验证检查点；
- 超时、网络中断和人工重试不重复下载，不允许同一请求重复调用 Kimi；
- 连续任务、重复提交、磁盘不足、平台登录失效和断网恢复均有明确回执；
- 至少进行一轮长时间单并发稳定性测试并记录资源占用。

完成门槛：失败恢复固定集通过，规模测试没有重复扣费、孤儿进程、临时媒体泄漏或错误成功回执。

## P5：公开 Alpha

状态：Windows `v0.1.0-alpha.10` 已完成 Pre-release、主线测试和 Windows 构建；xos 已用 `alpha.9` 证明 `msstore` 绕行修复有效，`alpha.10` 还需复验自动打开两个工作区。发布冻结前还差同版 COS/官网切换，以及一轮完全按官网路径执行的 B站陌生用户首装闭环与缓存复验。完整双平台陌生用户路径改为上线后加固项。Mac 公开版由独立任务推进，不阻塞 Windows 验收。

- Windows 与 Mac 分别发布版本化安装包、SHA256、SBOM、已知限制和卸载说明；
- 未签名版本明确 SmartScreen/Gatekeeper 风险；签名、公证和自动更新作为发布增强单独验收；
- 官网、README、安装器和真实产品能力保持同一口径；
- 发布后只维护真实可复现的证据，不提前承诺托管版能力。

完成门槛：新用户按官网路径从下载走到微信提交并在 Obsidian 看到笔记，不需要开发者远程操作。

## 暂停项

- 抖音/B站“分享给自己”、钉钉等第二输入通道。

这些方向保留在产品规划中，但不得分散公开 Alpha 的首次使用闭环。
